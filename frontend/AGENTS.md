# Dadnovin — Frontend

Vite + React 19 + TypeScript SPA for «گروه حقوقی دادنوین» (DADNOVIN LEGAL GROUP). Persian, RTL-first.

## Commands

- `npm run dev` — dev server
- `npm run build` — typecheck + client build + SSR bundle + static prerender of every route into `dist/` (SEO: crawlers get full HTML)
- `npm test` — vitest (jsdom) unit tests
- `npm run typecheck` — types only

## Conventions

- All public copy lives in `src/content/lawyers.fa.js` — never hardcode brand/service/lawyer strings in components.
- `privateNotDisplayed` fields in the data file are internal-only; they must never be rendered, serialized into markup, sent to analytics, or put in JSON-LD.
- Routes: `/`, `/about`, `/services` (+ `#<service-slug>` anchors), `/consultation`, `/contact`, `/track`. Add real pages before linking — no dead links. Register new routes in `AppRoutes`, `seo` map, `sitemap.xml` and `scripts/prerender.mjs`.
- Design tokens in `src/styles/tokens.css` — generated with the color-palette skill (full `--ink-50…950`, `--gold-50…950`, `--navy-*` scales + semantic `--bg/--surface/--card/--border/--text/--text-muted/--accent*` with dark defaults and an `--lt-*` light set). Warm stone black `#1C1917` (ink-950), amber gold `#C8922D`/`#F5C66E`, bone ivory `#F5F3EE`, deep navy band `#131B30`. **No blue/purple, no dirty gray, no pure white/black text.** Gold is for accents only — numbers, active states, hairlines; never flood the page. Light bands (white/gray/cream/goldwhite) rescope to the `--lt-*` set: soft ink text `#292019`, muted `#5F574C`, AA-safe accent `#7A4A05`. Card/panel surfaces are a single clean slate gradient (`ink-2 → ink-0` + faint sheen/gold glow) — no marble veins, streak lines, or noise textures; keep section backgrounds flat so the page reads as one surface. Hero is the exception: `hero-marble.webp` texture + 3-stop warm ramp + scrim + ghost «دادنوین» wordmark.
- Section bands live in `global.css`: `.band--ink|navy|white|gray|cream|goldblack|goldwhite` on a wrapper + `SectionWave` (`from`/`to`/`flip`) between bands. **Locked palette**: hero lux black `#0B0B0F` (marble + gold particle dust) → `#about` bone `#F6F3EC` → `#approach` deep navy `#061021` → `#services` warm gray `#E8E5DE` → `#team` navy → `#consult` bone → footer charcoal `#121212` (strict dark/light alternation). Light bands (white/gray/cream) rescope `--color-text`/`--gold-*` tokens and set `--band-self`; ink/navy/goldblack/goldwhite are dark bands keeping the ivory/gold theme. Dark panels listed in the `:is(...)` selectors keep the dark palette on light bands. Sub-pages compose `.page-band` wrappers; every page's last wave must end at `goldwhite` (the footer band).
- Homepage sections sit on flat colour bands — a dark→light scale (مشکی→سورمه‌ای→سفید→فیلی→استخونی): `.band band--ink|navy|white|gray|cream` paints the band; `band--navy` keeps the dark theme and the three light bands rescope `--color-text/-2`, `--color-border` and the gold channels to deep bronze. Order: hero ink → about navy → picture white → services cream → lawyers gray → cta white → footer. Bands are seamed by `<SectionWave from to flip>` (no hard rules); inside light bands, dark panels (`.sg-card`, `.svc`, `.rcard`, `.trust__item`, `.how-strip__item`, `.consult-point`, `.consult-aside`, `.contact-panel`, `.cform`) re-scope back to ivory/gold — extend that `:is(...)` list for any new dark panel. Translucent-ink panels are also forced solid on light bands (they'd otherwise blend to muddy gray).
- Sub-pages are banded too (`<div className="page-band band band--X"><div className="container">…` + SectionWave seams + a trailing `to="deep"` wave into the footer): `/about` = white head → navy members → gray trust; `/services` = ink gallery → white svc-list → cream how-strip; `/consultation` = white head+points → cream timeline → gray faq → ink form; `/contact` = white head → navy layout.
- Homepage uses the "chapter" system: each section gets a `ChapterHead` (۰۱…۰۵) and a stable `id` (`about`, `approach`, `services`, `team`, `consult`). All content is permanently visible — no accordions/FAQ patterns.
- Sections: `ledger` rows (about + animated `CountUp` stats), `service-card` 3×2 grid with pointer-tracked glow (services), `lawyer` media/text rows (alternating flip), `timeline` nodes (consultation page).
- `/about` page: hero head + gold-ruled `about-hero__motto` tagline, `page__body` paragraphs, then `.members-grid` → two `ResumeCard` (`components/ResumeCard.tsx` + `.css`, `.rcard.*`) — marble resume cards with kicker/name/Latin-name/degree/bio, 3-cell `.rcard__stats` strip, two-column expertise bullets, education, and per-card consultation CTA + tel/email lines. Then the `.trust` row + closing CTA with direct member phone links. Member `resume`/`contact` data lives inside each `lawyers[]` entry; `portrait: null` renders the branded emblem placeholder (no fake photos — drop the real file into `public/images/` and set the path). Pointer glow helper is `utils/pointerGlow.ts` (`--gx/--gy` vars) — reuse it for new cards.
- Hero is a physical split field (`direction:ltr`, `isolation:isolate`, `min-height: max(calc(100svh - var(--header-h)), 44rem)` — the floor keeps panel copy unclipped on zoom/short viewports): left ≈56% luxe black (`--ink #07080a` + spotlight confined to the statue) holding the figure, right `clamp(440px,44%,780px)` a real `.hero-panel` element in `--bone #efeadf` whose left edge is a half-ellipse (`border-radius:50% 0 0 50%/50% 0 0 50%`) traced by a champagne line (`.hero::after`, panel width +5px, solid gold band 18–82%, `opacity:.75`). The panel rescopes light tokens (`#14161a/#3a3d44/#7a5c16`, accent word `#8a6a1f`). **The hero→about seam is the hero's OWN bottom edge**: a `mask-image` wave bites ~3–7% off the section bottom and `#about` slides 5rem underneath (`z-index:-1`, +5rem padding compensation) so its bone field shows through the cut — NO overlay element ever touches the panel (this replaced the old `::before` vignette + SectionWave, which caused the scroll 'arc break' + gray-blob bugs). Copy stack: kicker → static motto → H1 → `.hero__rule` (56px gradient, in-flow) → `.hero__hook` (gold-bar pull-quote) → subtitle → CTAs → meta ledger (numbers in `<strong>`). CTAs use the shared 3-D system in global.css: `.btn` base + `.btn--primary`/`.btn-navy` (navy plate on light, molten gold only inside dark bands — `.hero-panel` descendants are excluded via `:not(.hero-panel *)`) + `.btn--ghost` (dark hairline on light, cream on dark). On ≤56rem the split turns vertical: stage ~45svh on top, panel below with `border-radius:50% 50% 0 0/64px` and `margin-top:-2.75rem` overlap, gold arc via `.hero-panel::before`. The bronze statue + `StatueParticles` point cloud stand in the black zone (`.hero__stage` fills the field minus 8% arc gap; statue `bottom: clamp(4.5rem,10svh,7rem)`, height `min(42rem,74svh)`, gold rim drop-shadow). The stage mounts client-side only — prerendered HTML and SSR skip it.
- `StatueParticles` (three.js/WebGL, code-split) drives the statue dust effects — photo-hole reveal: canvas UNDER the alpha image, `--hx0…/--hr9` radial mask holes on the img (needs the 10-layer `.is-live` mask rules duplicated per host: `.sg__statue.is-live`, `.hero__statue.is-live`). `BLOB_COUNT=10`: [0] cursor, [1..3] one-shot arrival wave, [4..9] ambient lissajous patches (larger, wider-ranging, staggered cycles). Blob influence is angular-noise-deformed in the vertex shader — irregular smudges, never clean circles; revealed points scatter into the air (upward drift + turbulence + continuous slow float). Colours: ~80% near-black dust + ~20% bright champagne gold (top `aRand` quintile, glows ×1.3). `FIT.scale=0.96` keeps the whole cloud inside the photo alpha — dust must never poke out from behind the figure. Used by the hero and the `/services` page header (`.sg__statue`; the homepage gallery head is `.sg__head--plain`, statue-free). Pass `host` (observer/pointer scope) and `className` (canvas mask class). Model sources (HTML demos) live in `src/assets/models/` — never ship them in `public/`.
- There is no scroll-scrubbed intro — the hero itself is the cinematic opening (one-time mount animation only; never scroll-linked motion). Hall master: `src/assets/intro-hall.png` → shipped variants `public/images/intro-hall-*`.
- CSS is colocated per component (`Header.css`, `Footer.css`, `ConsultationForm.css`) plus `src/sections/home.css` and `src/pages/pages.css`. Use logical properties (`inset-inline-*`) — the page is RTL.
- Icons: `lucide-react` for UI icons. Homepage sections are seamed with `<SectionWave from to flip>` (two-ridge SVG drape of the upper band colour over the lower — never a hard line). `<SectionDivider>` takes no props — every divider renders the same `symbol-column-*` 3D mark on one shared axis (lines run along the plinth); never use logo/brand artwork in dividers, and never place a divider immediately before the footer. Service-card symbols come from `services[].symbol` → `/images/symbol-<name>-{384,640}.webp`.
- Header: single CTA instance inside `.site-nav` (CSS places it). Always dark glass (`.site-header__bg`, ~0.82 alpha → 0.96 when `.is-scrolled`) — over the intro and the site. `backdrop-filter` must stay on `.site-header__bg` — never on `.site-header` itself (it would become a containing block for the fixed drawer/backdrop). Scroll progress + sliding nav marker write styles directly to DOM (no re-render).
- Smooth scrolling: `SmoothScroll` mounts a shared Lenis instance (components/SmoothScroll.tsx, `getLenis()`); `ScrollManager` routes hash/restore jumps through it. Disabled under reduced-motion. Keep the Lenis reset rules in `global.css`.
- Motion: `Reveal` with `variant` prop (`up|x-start|x-end|clip|line|fade`), one-shot scroll reveals; `prefers-reduced-motion` respected everywhere. No animation libraries — CSS transitions/keyframes only.
- Forms submit to the real backend: `ConsultationForm` → `POST /api/v1/consultations`, `ContactForm` → `POST /api/v1/tickets` (both return tracking code + access code shown to the visitor, with a `/track` link). If the API is unreachable they fall back to an honest copyable summary — never fake a "sent" state. API client is `src/services/api.ts`; phone validation is `src/utils/phone.ts`.
- `/track` is a real public page (`pages/TrackPage.tsx`): visitor enters tracking code + access code (or phone) → `POST /api/v1/public/track`; replies go to `/public/track/reply`. Registered in `AppRoutes`, `seo.track`, `sitemap.xml`, `scripts/prerender.mjs`.
- CMS content overlay: `content/remote.ts` fetches `/public/settings|pages|lawyers` after mount and mutates the exported content objects in place (`RemoteSync` in `app.tsx` re-renders once). Static content is the fallback when the API is down — always keep every `home.*`/`aboutPage`/… merge guarded so a missing key never throws.
- SEO: per-page meta via `useSeo(page, path)` + `seo` map in the data file; static JSON-LD in `index.html`; prerender script injects app HTML + per-route meta.
- `public/images/` ships only optimized, referenced assets (webp + png fallback for alpha art, jpg for photos; explicit w/h). Masters live in `src/assets/` (`intro-hall.png`, `picture-update.png`, `main-background-update.png`, `dadnovin-logo.png`, `dadnovingroup.png`, `symbols/`) — never copy them back into `public/`; generate variants with PIL instead. `picture-*` are transparent cutouts (white-keyed + alpha cleanup); `*-portrait-{440,720}.webp` are opaque composites on a deep-navy radial (`#101c33→#050b18`; flood-cut light studio bg + 2px edge un-blend — regenerate with the same numpy/PIL approach if a real photo replaces them).
- Fonts: custom Persian display system — **Lalezar** (OFL, `public/fonts/lalezar-arabic-400.woff2`) for h1/h2/brand display titles at weight 400 (it ships one weight — never set 700+ on display elements or the browser faux-bolds it), **Estedad variable** (OFL, `public/fonts/estedad-{arabic,latin}-var.woff2`) for body/UI/h3 at 400-700. Both loaded via `@font-face` in `global.css` with `font-display: swap`. `@fontsource-variable/vazirmatn` (fallback) + `@fontsource/cormorant-garamond` (latin wordmark) via npm. Title colours: `--title-bone #F6F3EC` / `--title-gold #C6A15B`; dark-band h1/h2 get a restrained emboss `text-shadow`. `--font-fa` / `--font-display` / `--font-en` tokens + responsive `--text-h1/h2/h3/body/caption` clamps and `--lh-display/body/ui` line-heights in `tokens.css`.
